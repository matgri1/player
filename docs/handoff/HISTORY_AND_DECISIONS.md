# История работы и решения

Хронология (ноябрь 2026), чат с Claude в облачной сессии, репозиторий `matgri1/player`,
ветка `claude/kuy-vietnam-services-site-646vgc`.

1. **Старт.** Нужен сайт экосистемы «Куй» в Куйньоне: визараны, обмен, русская кухня, туры,
   позже маркетплейс. Языки EN (по умолчанию) / RU / VI. В репозитории уже лежал чужой
   `index.html` (киноплеер) — его не трогали, сайт в папке `kuy/`.
2. **Ориентация на американцев.** Переделали дизайн «как у привычных американцам сайтов»:
   светлый, белые карточки, синие кнопки, простой язык, WhatsApp/Messenger, FAQ, произношение
   «kwee-nyon». Предупредили: «kuy» по-тайски — грубое слово; возможно лучше бренд QUY.
3. **Подстраницы**: визаран (сначала заглушка), калькулятор обмена, меню еды (SVG-заглушки,
   так как фото из облака не скачать).
4. **Интерактив**: анимированный чат, часы Куйньона, выбор мест в турах, корзина еды.
5. **Реферальная программа Kuy**: без регистрации. Код выдаётся вручную, привязан к номеру
   WhatsApp или аккаунту Telegram (WhatsApp/Telegram сами подтверждают номер). Ссылки `?ref=`,
   код автоматически добавляется в сообщения. Для русскоязычных главный канал — Telegram.
6. **GitHub**: сначала не было доступа (403), владелец установил Claude GitHub App — всё запушено.
   GitHub Pages владелец включает сам (`Settings → Pages`, ветка выше), адрес
   `https://matgri1.github.io/player/kuy/`.
7. **Архив бота QUY Travel** — изучили (см. QUY_TRAVEL_NOTES.md). Решение владельца:
   **не переадресовывать**, а **перенести весь процесс записи на сайт Kuy**, в синем дизайне,
   с подсказками для американцев. Сделали вкладку «Записаться» + слипбас-анимацию.
8. **Вьетнамская атмосфера**: слипбас (вместо машинки, которая «ехала задом»), пейзаж
   (море, пальмы, башня Чам, рис, буйвол, нагорье, кофе, КПП), рассвет → день, встречные байки.
9. **Калькулятор «Когда ехать?» и чек-лист** — тестово на сайте. Бот напоминаний пока пустой
   (владелец добавит **другого тестового** бота, не @quytravel_bot). Чек-лист потом переедет в бота.
10. **Админка**: владелец хотел видеть, кто куда записывается и какие группы собираются.
    Админку на публичном сайте не делали (небезопасно). Решение: «делаем как будто уже на
    сервере» — написан сервер `server/` (API + админка), проверен на временной PostgreSQL.

## Принятые решения (кратко)
- Статический сайт без сборки — проще редактировать и переносить.
- Сервер Kuy — тот же стек, что у QUY (Node/Express/PostgreSQL), отдельная база и сервис.
- Заявки с сайта пока в своей таблице `kuy_visa_requests`; объединение с QUY — позже.
- Никаких изменений в действующей системе QUY без явного разрешения владельца.
- Секреты — только в `.env` на сервере.
- Факты о визах формулируем осторожно («правила меняются, проверим»): штамп 45 дней —
  для подходящих паспортов (напр. РФ), гражданам США/Канады/Австралии нужна e-visa.
